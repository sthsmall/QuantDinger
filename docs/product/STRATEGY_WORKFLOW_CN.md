# 从策略想法到运行

QuantDinger 的策略生命周期包括假设、编码、校验、回测、保存、部署和监控。每一步都保留独立的检查点，避免把“能运行”误认为“适合实盘”。

## 1. 写清策略契约

开始编码前明确：市场、标的、频率、入场、退出、仓位上限、费用、方向和停止条件。对于 Crypto swap，显式声明方向能力；现货和当前非 Crypto 策略按 long-only 设计。

## 2. 在策略编辑器中实现

优先从 Strategy API V2 模板开始。保持 `initialize`、订阅、universe 与 `handle_data` 的职责清晰。使用完整市场标识，不根据显示名称猜交易所或产品。

完整接口、manifest 和安全沙箱规则见 [Strategy API V2 开发指南](../trading/STRATEGY_DEV_GUIDE_CN.md)。

## 3. 校验并保存版本

运行源码校验，处理所有错误和警告。保存时记录策略目的和重要参数；对改变 universe、频率、仓位或退出逻辑的修改建立新版本，便于结果比较和回滚。

## 4. 回测

选择能覆盖预热期和多种市场状态的时间范围。检查数据覆盖、基准、费用、滑点、资金费和流动性限制。阅读[回测中心指南](BACKTEST_CENTER_CN.md)中的结果核对方法。

## 5. 创建停止状态的部署

部署应先创建为 stopped。确认凭证、市场、结算币种和产品类型匹配，再使用 `signal` 模式验证通知与状态恢复。不要让一个部署混用不兼容的市场或账户。

## 6. 启动和监控

实盘前完成[实盘安全清单](../trading/LIVE_TRADING_SAFETY_CN.md)。启动后监控运行状态、订单、持仓归属、未知差额、通知和错误日志。异常时先停止新开仓；需要时停止策略或使用紧急停止。

## 发布前检查

- 源码与 manifest 校验通过。
- 回测数据范围和预热完整。
- 费用、滑点、资金费和最小下单规则已确认。
- 交易凭证与策略市场匹配。
- 信号模式已观察足够时间。
- 停止、恢复和人工应急路径已验证。
